# Agent Spec

## Overview

Universal Inventive Problem Solving agent. Input: any inventive problem (text). Output: full 5-step reasoning trail as JSON.

Pipeline steps (each a separate, inspectable artifact):
1. **Problem** — intake and normalize input
2. **Contradiction** — LLM extracts TRIZ improving/worsening parameter pair (validated: values ∈ 1–39)
2a. **Lookup** — deterministic code maps parameter pair → TRIZ inventive principles via 39×39 matrix JSON
3a. **TRIZ Candidates** — LLM generates ≥3 candidates, one per returned principle; code enforces traceability
3b. **SCAMPER Candidates** — code iterates 7 SCAMPER operators (S/C/A/M/P/E/R), LLM generates ≥3 candidates
1a. **Criteria** — LLM extracts problem-specific evaluation constraints → rubric (generic: resolves contradiction, feasibility, cost/scale + problem-specific)
4. **Evaluation** — LLM scores each candidate 0–100 per rubric criterion with justification
5. **Choice** — deterministic code selects winner by argmax of aggregated scores

Demo problem: **Problem 4 — Preventing Oil Spills in Maritime Transport (SDG 14)**.
System must be universal: no prompt, constant, or criterion may reference any specific problem.

## Example Use Cases

**Input:**
```
Moving crude oil across oceans is only economical at scale. When something goes wrong—a collision,
grounding, or structural failure—the resulting spill can be catastrophic. Your task: propose a way
to substantially reduce the risk and severity of oil spills from maritime transport. Constraint:
keep transport as-is, but keep marine life safe.
```

**Output (abbreviated):**
```json
{
  "problem": { "normalized": "...", "domain": "maritime transport" },
  "contradiction": { "improving": 27, "worsening": 31, "justification": "..." },
  "lookup": { "principles": [35, 10, 2, 40] },
  "trizCandidates": [
    { "principle": 35, "name": "Parameter Changes", "idea": "...", "traceId": "triz-35" }
  ],
  "scamperCandidates": [
    { "operator": "S", "name": "Substitute", "idea": "...", "traceId": "scamper-S" }
  ],
  "criteria": ["resolves contradiction", "feasibility", "cost/scale", "transport continuity"],
  "evaluation": [
    { "candidateId": "triz-35", "scores": { "resolves contradiction": 80 }, "total": 310 }
  ],
  "choice": { "winnerId": "triz-35", "reasoning": "highest argmax score" },
  "tokenUsage": { "total": 4200 }
}
```

| Tool | Purpose | Auth |
|------|---------|------|
| Gemini (google-genai) | Contradiction extraction, candidate generation, criteria extraction, evaluation | GOOGLE_CLOUD_PROJECT / Vertex AI |
| TRIZ matrix JSON | Deterministic 39×39 lookup → inventive principles | Static file, no auth |
| Google Search (grounding) | Optional: enrich contradiction or candidates with web evidence | Vertex AI grounding API |

## Constraints & Safety Rules

- **Universal**: no step may reference any of the 7 hackathon problems by name or ID
- **Parameter range**: TRIZ parameters must be integers 1–39; reject and re-prompt if out of range
- **TRIZ traceability**: every TRIZ candidate must carry a `principle` field traceable to the lookup output
- **Deterministic choice**: winner = argmax of total scores; code, never LLM
- **SCAMPER iteration**: code iterates operators; LLM generates content only — operator selection is not LLM's job
- **Eval-safe**: no prompt may hard-code an expected answer for any of the 7 problems
- **Token budget**: log token usage per step; warn if total > 10,000 for a single run

## Success Criteria

- `agents-cli run "Oil spills problem..."` returns full 5-step trail JSON without error
- TRIZ parameters ∈ 1–39 (code-validated, not LLM-asserted)
- ≥3 TRIZ candidates, each with traceable `principle` field
- ≥3 SCAMPER candidates, each with traceable `operator` field
- choice.winnerId == argmax(evaluation[*].total) — verified by code
- Eval runner passes all 7 hackathon problems + ≥3 edge cases (garbled input, off-domain, empty)
- Agent deployable to Cloud Run; jury can hit URL and get a response

## Architecture & Sub-Agents

Single-agent pipeline (no sub-agents at MVP). All steps run sequentially in one ADK agent. Each step
is a separate tool call so the trace is fully inspectable. TRIZ lookup and argmax are plain Python
functions registered as ADK tools (deterministic, unit-testable, no LLM involved).

## Non-Functional Requirements

- Deployment target: **Cloud Run** (jury needs public URL; hackathon)
- Session storage: in-memory (stateless per run; no cross-session recall needed)
- CI/CD: Google Cloud Build
- Language: Python (ADK)
- NX monorepo integration: scaffold into `apps/agent/` within the existing NX workspace
